The load-bearing insight

Once items come from config/static-markets.json (already in repo — 5 modes × 10 items with true values) via a pure function itemForRound(mode, roomId, hostTokenHash, roundNumber), nothing async can fail mid-round. The entire F-02 pending-effect retry/backoff machinery (~400 alarm lines), F-07 bounce caps, private item storage, and the error phase have no failure class left to handle — they are deleted, not patched.

Cut vs Keep

Keep — this is the game

  • src/lib/game/ state machine — propose → negotiate → quote → choose side → settle zero-sum PnL
  • src/lib/room/ protocol core — tokens, commands, snapshots, persistence
  • Worker DO skeleton — routes, WebSocket fanout, storage transactions, dedupe
  • All core UI — GameShell, forms, scoreboard, action log
  • F-08 socket liveness sweep + TTL alarms

Cut

  • Gemini AI generation — dep, providers, prompts, secrets plumbing
  • Amazon scraper + custom-query flow (route, form, flags, fields, mode)
  • Provider-failure machinery — F-02 retries, F-07 bounce cap, error phase
  • Shot clocks F-05/F-06 (default) + test-expire-turn route
  • Junk: persephone/, PR_BODY.md, dead constants
